# RAG 评测接入说明（参赛方一页纸）

目标：在同一套考题上，公平比出各 RAG 的质量，并告诉你**差在哪一环**。

你**不需要**改用我们的框架，也**不需要**让我们碰你的代码。接入 = 写一个导出脚本，把你的作答结果按固定格式存成 `run_log.jsonl`（答题卡）交回来。

---

## 一、3 步接入

| 步 | 你做什么 | 产出 |
|---|---|---|
| 1 | 拿 `templates/adapter_template.py`，实现里面的 `ask(question)` | 能跑通你自己 RAG 的脚本 |
| 2 | 跑 `python templates/adapter_template.py --dataset dataset/dataset_public.jsonl --out run_log.jsonl` | **答题卡** `run_log.jsonl` |
| 3 | 自查通过后，把 `run_log.jsonl` 交回 | 完成 |

```bash
# 步骤 2：跑题（先用 --limit 5 调试）
python templates/adapter_template.py --dataset dataset/dataset_public.jsonl --out run_log.jsonl --limit 5

# 步骤 3：自查（0 个错误才能交）
python -m rag_eval.cli validate --dataset dataset/dataset_public.jsonl --run-log run_log.jsonl
```

> 自查要装一下：`pip install -r requirements.txt`（只有 `jsonschema` 一个依赖）。
> 如果主办方已经把 `rag_eval/` 发给你，直接用；否则把报错信息发给主办方代跑也行。

## 二、答题卡长什么样

`run_log.jsonl`，每题一行：

```json
{"system_name":"my-team","question_id":"ent_001",
 "answer":"国内 100 元/天，境外 150 元/天。","abstained":false,
 "retrieved_chunks":[{"chunk_id":"travel_policy_2025__005",
                      "doc_id":"travel_policy_2025",
                      "rank":1,"score":0.74,"text":"## 伙食补助

伙食补助按自然天数计发…"}],
 "context":"[1] ## 伙食补助

伙食补助按自然天数计发…",
 "citations":[{"claim":"国内 100 元/天","chunk_id":"travel_policy_2025__005"}],
 "latency_ms":1187,"input_tokens":3120,"output_tokens":96,"error":null}
```

**只有 3 个字段是必填的**：`system_name`、`question_id`、`answer`。
其余给了就多算指标，不给就显示 N/A —— **不会因为缺字段被算 0 分**，但排行榜会标注你的覆盖率。

---

## 三、给多少字段，评多少指标

| 你提供了 | 能评什么 |
|---|---|
| 只有 `answer` | Answer Correctness / Relevance / Completeness / Abstention |
| + `retrieved_chunks` | 再加 **Recall@K / Precision@K / MRR / NDCG**（检索层） |
| + `context` | 再加 **Context Recall / Context Precision / Faithfulness**（能准确判「是否忠于证据」） |
| + `citations` | 再加 **Citation Correctness / Precision / Recall** |
| + `latency_ms` / `input_tokens` / `cost_usd` | 再加 **P95 延迟、cost/query、Pareto 图** |
| + `query_rewritten` / `trace` | 不算分，但出错时我们能帮你定位是 Embedding 慢还是 Reranker 慢 |

**强烈建议给到 `retrieved_chunks` + `context`**。只交最终答案，就退化成普通问答评测，
而且一旦答错，无法判断是**没找到**还是**没用好**——你自己也拿不到那份「该改 Embedding 还是改 Prompt」的诊断。

## 四、5 条硬规则（违反会被判无效）

1. **一文件一系统**：一份 `run_log.jsonl` 里 `system_name` 必须唯一，多系统请分多份文件提交。
2. **题号对齐**：`question_id` 必须照抄 `dataset_public.jsonl`，不许增删改题、不许跳题（跳题按超时计）。
3. **chunk_id 用官方编号**：`retrieved_chunks[].chunk_id` 必须取自 `corpus/chunks.jsonl`（对照表 `corpus/chunk_index.json`，形如 `travel_policy_2025__005`）。**标准答案按这套编号标注**，编号对不上 → 检索层全算不出来，等于白交。`validate` 会核对编号是否真实存在。
4. **不许拿答案**：`dataset_public.jsonl` 只含题目，标准答案在主办方手里。评测方保留抽测与反作弊审计权（详见 README「防作弊边界」）。
5. **超时/异常照实填**：`answer` 填 `""`、`error` 写原因。谎报成功比超时扣分更狠。

---

## 五、几个容易踩的坑

- **`retrieved_chunks` 请给重排后的最终顺序**，`rank` 从 1 开始连续且不重复。
- **`context` 是「真正送给 LLM 的那段文字」**，不是原始文档，也不是只有 chunk 摘要。截断了就要如实反映，因为「正确 chunk 在库里但没进 context」会被归因为 Context Error，和「根本没搜到」是两回事。
- **无答案题要敢拒答**：`abstained: true` 且 `answer` 写「根据现有知识库，无法找到相关信息」。硬编一个答案会被计为幻觉（No-answer Error），这一项权重很高。
- **`citations` 的 `claim` 写你答案里的原句**，不是你自己的解释。引用错了就是引用错，会单独算 Citation Correctness。
- **时间用毫秒**（`latency_ms`），端到端从收到问题到吐出答案，含检索和生成。

---

## 六、你会拿到什么

1. **Scorecard**：你的各项指标 + 全场对比（每列最优高亮）
2. **错误归因报告**：答错的题分别归到 Retrieval / Ranking / Context / Generation / Citation / No-answer 六类，并给出建议改哪个组件
3. **题型雷达图**：simple / multi-hop / long / temporal / no-answer / ambiguous / multi-doc / hard 八类的强弱
4. **逐题复核页面**：每题你的答案、检索到的 chunk（命中标准答案会高亮）、判分理由

**看别人填过的答题卡**：`templates/run_log_sample.jsonl` 有 3 条完整示例
（含正常作答 / 无答案拒答 / 只填部分字段三种形态），照着填最快。
里面的 `answer` 是占位文本，不代表正确答案。

**你的 chunk_id 填对了吗？** 公开考卷没有标准答案，但可以自查编号是否真实存在：

```bash
python -m rag_eval.cli validate --dataset dataset/dataset_public.jsonl --run-log run_log.jsonl
```

`validate` 会逐条核对 `chunk_id` 是否在 `corpus/chunk_index.json` 里，填错会指到具体行号。
若你的检索引擎自产 ID（如 md5 哈希），请在入库时把官方 chunk_id 塞进元数据，
映射成 `retrieved_chunks` 时再取出来 —— 详见 README「非官方 ID 系统如何对齐」。

有疑问找主办方。
