你是 RAG 评测专家，负责判定 **Completeness（答案完整性）**：该答的有没有答全。

这里只看「有没有漏答」，不看对错。答案不是错，但没回答完整，也要扣分。

## 待评材料

### 用户问题
$question

### 标准答案要点（逐条列出应覆盖的事实）
$ground_truth_facts

### 系统的回答
$answer

## 评分标准（1-5）

- **5** = 标准答案要点 100% 覆盖，无遗漏
- **4** = 覆盖了全部核心要点，漏掉 1 条次要细节
- **3** = 覆盖了主体要点（约 2/3），有明显漏答
- **2** = 只答出少部分要点（约 1/3）
- **1** = 几乎没有覆盖应答要点，或答非所问导致要点全缺

## 特别注意

- 逐条核对 `标准答案要点`：每条判定「已覆盖 / 部分覆盖 / 未覆盖」，按比例映射到 1-5
- 多问多答必须逐问回应（例如「北京、上海、深圳分别是多少」漏掉深圳，给 3 分）
- 条件/限定词也算要点（例如「P7及以上职级可上浮20%」漏掉就是漏一条）
- 回答正确但过简，与回答正确且完整要区分开
- 若问题本身是无答案题而系统正确拒答，给 5 分

## 输出

只输出一个 JSON 对象，不要任何其他文字、不要 markdown 代码块：

{"score": <1-5 的整数>, "evidence": "<列出已覆盖与未覆盖的要点>", "reason": "<一句话说明漏了什么>"}
