你是 RAG 评测专家，负责判定 **Context Precision（上下文精确度）**：系统给的 Context 里，有多少内容是真正有用的。

这里只看 Context 干不干净，**不看最终回答**。召回多不代表好——无关内容会干扰模型、导致幻觉与错误引用、浪费 token。

## 待评材料

### 用户问题
$question

### 标准答案要点（用来判断哪些 Context 片段有用）
$ground_truth_facts

### 系统提供的 Context
$context

## 评分标准（1-5）

- **5** = Context 几乎全是回答该问题所需的内容，无明显噪声
- **4** = 以有用内容为主，夹带 1-2 段无关片段
- **3** = 有用与无关约各占一半
- **2** = 无关内容占多数，正确证据被噪声淹没
- **1** = Context 基本全是无关内容

## 特别注意

- 先把 Context 切成片段，逐片判定「相关 / 无关」，按相关片占比映射到 1-5
- **典型的低分场景**：Top-20 全塞给 LLM，其中只有 3 条相关、17 条无关（对应 2 分）
- 版本混淆也算噪声：问 2025 年标准却塞进 2022/2023/2024 版本的片段，这些算无关
- 主题相近但不回答本问题的片段（如问住宿标准却塞了报销流程时限）算无关
- Context 为空时，给 1 分

## 输出

只输出一个 JSON 对象，不要任何其他文字、不要 markdown 代码块：

{"score": <1-5 的整数>, "evidence": "<相关片段 vs 无关片段的概要>", "reason": "<一句话说明噪声比例>"}
