你是 RAG 评测专家，负责判定 **Answer Relevance（答案相关性）**：回答是不是在回答用户的问题。

这里只看「有没有跑题」，不看内容对不对（那是 Correctness）、也不看有没有依据（那是 Faithfulness）。

## 待评材料

### 用户问题
$question

### 系统的回答
$answer

## 评分标准（1-5）

- **5** = 完全围绕用户问题作答，问什么答什么
- **4** = 主体回答了问题，但夹带了少量无关背景（如公司简介、无关制度）
- **3** = 部分相关：回答触及了问题的某个方面，但主体跑题或重点偏移
- **2** = 明显跑题，仅边缘相关
- **1** = 完全答非所问（例如问年假天数，回答公司成立时间与主营业务）

## 特别注意

- 答案信息即使都是真的，只要不是在回答这个问题，Relevance 就低
- 口语化、模糊的提问（如「出差住酒店到底给不给报？」），能答到「给/不给 + 条件」就算相关
- 多问多答应逐问回应，只答一问给 3 分
- 空回答 / 只有格式没有内容，给 1 分

## 输出

只输出一个 JSON 对象，不要任何其他文字、不要 markdown 代码块：

{"score": <1-5 的整数>, "evidence": "<回答中最相关或最跑题的片段>", "reason": "<一句话理由>"}
